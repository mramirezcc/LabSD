Análisis — ¿Por qué SOAP falla directo desde navegador?
1. Política CORS (Cross-Origin Resource Sharing) El navegador bloquea fetch a dominios distintos al origen de la página a menos que el servidor responda con Access-Control-Allow-Origin. Los servicios SOAP antiguos raramente incluyen ese header. 2. Construcción manual del XML SOAP Sin librerías nativas, el desarrollador debe construir el envelope XML a mano, incluyendo namespaces, SOAPAction en el header, y parsear la respuesta XML — proceso verbose y frágil comparado con JSON en REST. 3. Solución arquitectónica correcta Usar un backend intermediario (proxy_soap.py con Flask + Zeep) que consuma el servicio SOAP y exponga una API REST/JSON al frontend. El navegador llama JSON, el proxy traduce a SOAP.
